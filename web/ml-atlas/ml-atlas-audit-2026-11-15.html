  1. 这不是一个"玩具页面"，工程质量明显高于一般单文件项目。零外部请求、零网络依赖、零 eval，171 个条目 16 个必填字段 100% 完整，151 段 Python 示例全部通过 ast.parse，631 个参数说明无一低于 20 字。这批数据本身就是最值钱的部分。
  2. 安全做得比预期好，但有两个洞在"备份恢复"这条路径上。四类注入面全部转义正确（搜索回显、笔记、自定义条目、脏 JSON），但 importBackup 的自定义条目既没走 id 白名单也没做字段校验 —— 同一份脏数据走"导入 JSON"会被净化，走"恢复备份"却能原样进库。

01架构与工程结构84 / 100

数据、视图、交互三层分得清楚，缓存与局部重绘的设计不像手写单文件能有的水准。扣分主要来自"单文件"这个形态本身在 912 KB 量级下开始反噬可维护性。

Strength

做对的地方

  • 真正的零依赖：实测 performance.getEntriesByType('resource') 返回 0 条非 data 资源，断网、拷到 U 盘、发微信都能直接用。
  • 数据与视图分离：DATA / CATS / DIFFS 是纯数据，渲染函数只读不写，新增条目不动一行渲染代码。
  • 事件委托统一：全部交互走 document 上的 data-act 分发，无内联 onclick（实测 0 处），重建 DOM 不会丢监听。
  • 三层缓存：_all 合并结果、_hayById 检索串、_fKey/_fList 筛选结果，配 FILTER_VER 版本号失效，比"每次重算"快两个数量级（筛选 0.002 ms）。
  • 局部重绘：收藏/复习切换只重绘受影响的按钮（paintToggles），保住焦点与滚动位置。
  • 内容流水线：有通用注入器 + 字段断言（16 字段、四元组、说明字数、cat 合法性、id 重复），171 条不是手贴进去的。
Weakness

需要正视的结构问题

  • 体积构成不均衡：912 KB 里 59% 是内联 DATA、28% 是 base64 壁纸（262 KB，压缩收益极低），真正的 CSS + 逻辑只有 约 90 KB。壁纸是"不可压缩的负担"。
  • DATA 是 171 行超长行：注入器把每条压成一行 JSON，单行可达 10 KB 以上，任何 diff / 代码审阅都无法阅读。
  • 无 lint、无测试、无构建：所有验证靠 .workbuddy/tmp/ 里的一次性 CDP 脚本，会话结束即失效，下次改动无法回归。
  • 样式层有历史沉积：278 条规则、8 处 !important、24 处 backdrop-filter（其中若干已被后续规则覆写为 none），说明视觉方案迭代过多轮而未回收。

Optimization · 三条性价比最高的改法
  • 账面上最大的一笔：给 .entry 加 content-visibility:auto; contain-intrinsic-size:auto 260px —— 视口外卡片跳过样式计算与布局，31 ms 的布局成本可砍掉六到七成，一行 CSS。

级别问题证据与成因建议
P1 键盘无法到达详情页，513 个 Tab 停靠点 "查看完整代码"为 <span>，可聚焦 detail 入口 0/171；卡片 Enter 只做 select。实测 focusableDetailLinks = 0 把入口改成 <a href="#" data-act="detail"> 或 <button>；卡片内用 roving tabindex（只有 1 个 tabindex=0），并在列表前加"跳到结果"skip link。
P1 长列表滚动掉帧 滚动帧间隔 avg 21.6 / p95 42.1 ms；关闭 backdrop-filter 后 avg 16.6 / p95 21.8，减少卡片数几乎无改善。归因：固定层 blur 重采样 顶栏/子导航/dock 改半透明纯色或加 will-change:transform 独立成层；顺带给卡片加 content-visibility:auto。
P1 2 处公式推导错误 SAC 温度梯度写成 ∇(−log α·(log π + H̄))，正确为 −α·(log π + H̄)（log α 参数化时才是 dα/dlogα = α）；Dice 梯度 −2g_i(Σp+Σg) + 2Σpg/(Σp+Σg)² 的括号范围错，应为 −[2g_i(Σp+Σg) − 2Σpg]/(Σp+Σg)²。 直接替换 sac 的 math.steps[3] 与 dice-loss 的 math.tex[2]／formulas[2]，同步改两处 formulas 纯文本。
P2 备份恢复不过白名单、不校验字段 同一份脏备份走 importCustom 被净化，走 importBackup 原样入库：CUSTOM = ["__proto__","constructor","中文","badshape","ok-9"]，5 条全缺 code/summary/cat，FAV 混入 __proto__。成因：importBackup 直接 push(item) 把 importCustom 里的"cleanId + 必填校验 + 字段归一"抽成 normalizeEntry(item)，两条入口共用；不完整的条目计为 skipped 并在 toast 里报数。
P2 同批次重复 id 不去重 一次导入两个 id:"dup" 全部入库，两卡片共用一个 id，后一条永远打不开。成因：byId 读缓存 _all，批内未失效 循环内维护本地 Set 记录本批已用 id，与 byId 双重判断。
P2 残缺条目进详情页抛异常 TypeError: Cannot read properties of undefined (reading 'split')（条目无 code 时）。实测在备份恢复 + 详情页复现 codeHTML 内部对 String(code||'') 兜底；renderDetail 缺 code/params 时显示"该条目内容不完整"占位而非崩溃。
P2 整页 render() 39.7 ms 拆解后 31.5 ms 是 171 张卡片的一次全量布局；筛选/切分类/部分收藏操作会触发整页重建，超过一帧 2.4 倍。实测 layoutCost = 31.5 ms 短期用 content-visibility；中期把搜索/筛选统一走已有的 renderGridOnly()，只重绘网格与计数，不动侧栏与速览。
P2 dice-loss 参数表与代码签名不符 参数表列了 weight，但 DiceLoss.__init__(smooth, per_class, from_logits) 无此参数；照文档写 DiceLoss(weight=0.5) 会 TypeError。 要么给 DiceLoss 加 ce_weight 并在内部组合 BCE，要么把该参数移到 DiceBCE 名下并改名 dice_w。
P2 18 条公式缺 tex，风格退化 第 2/3 行 tex 为空时回退纯文本，同一张公式卡片里两行是排版公式、一行是纯文本，观感割裂（如 apriori、fm、sarimax）。 给这 18 条补齐 tex 即可；补之前可先让 mathBlock 对纯文本行加统一 class，视觉上至少不突兀。
P2 移动端 dock 遮挡正文 375 px 下 .dock 为 position:fixed、227×41、top 727，压住最后一张卡片。实测 cardsBehindDock = 1 移动端给 #main 加 padding-bottom: 72px，或移动端把 dock 改为静态条吸附到底部内容流里。
P3 移动端 553 个触控目标 < 32 px 卡片收藏/复习图标按钮在高密度布局下过小，低于 WCAG 2.5.5 的 44 px 建议。 移动端把这两个按钮的最小点击区提到 40×40（可用伪元素扩展热区，不改视觉尺寸）。
P3 173 个 div/span 承载点击 分类标签、锚点、复制公式、删除笔记等交互元素不可聚焦、无角色。 逐类替换为 button；纯展示类的保留但加 aria-hidden 并在父级提供语义。
P3 Blob URL 不回收 导出备份实测 revokeObjectURL 调用 0 次。 download() 里 setTimeout(revoke, 0) 或直接在 click() 后 revoke。
P3 localStorage 满时静默失败 配额约 5 MB 实测可复现 QuotaExceededError；save() 只 toast 一次，用户可能以为笔记已保存。 写入失败时置一个"存储异常"角标常驻在顶栏，并引导导出备份；笔记保存失败时保留草稿不清空。
P3 lang / updated 元数据不统一 NumPy/numpy、SciPy/scipy 两两重复；updated 147 条挤在两天，语义模糊。 统一为 Python 3 · NumPy 写法；把 updated 明确为"内容修订日"，批量导入的条目留空并在 UI 上不显示。
P3 averaging 字段过薄 input「x；各模型已 fit」、output「平均预测 ŷ」，远低于全站均值。 补成与其它条目同密度的形状描述（如 probas: [n_models, n, n_classes]）。
P3 2 个顶栏按钮仅靠 title 命名 导入、搜索按钮无可见文字、无 aria-label，只有 title。 补 aria-label；同时把 6 个只有图标的按钮统一补上。
