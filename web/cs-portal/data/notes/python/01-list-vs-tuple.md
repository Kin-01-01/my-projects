# Python 的 list 与 tuple：不只是可变与不可变

「list 可变、tuple 不可变」——这是最常见的解释，也是最不够用的解释。真正会在写代码时咬人的，是下面这四件事。

## 一、能不能当字典的键

```python
d = {}

d[(1, 2)] = 'tuple 可以'
d[[1, 2]] = 'list 不行'     # TypeError: unhashable type: 'list'
```

为什么？因为字典用**哈希值**定位元素。哈希的前提是"这个值不会变"——不然存进去之后对象变了，哈希值也变了，字典就再也找不到它了。

所以规则不是"不可变就能当键"，而是：**可哈希（hashable）才能当键**。

而 `tuple` 只有在其**所有元素都可哈希**时才可哈希：

```python
hash((1, 2))            # ✅
hash((1, [2, 3]))       # ❌ TypeError —— 里面装了 list
```

## 二、内存布局差多少

```python
import sys

lst = [1, 2, 3, 4, 5]
tup = (1, 2, 3, 4, 5)

print(sys.getsizeof(lst))   # 104 （64 位 CPython）
print(sys.getsizeof(tup))   # 80
```

`tuple` 更省内存，原因是 CPython 的实现：

- **list**：维护一个**指向元素指针数组的引用**，而且数组会**超额分配**（over-allocate），留出余量方便 `append`。元素本身存在别处。
- **tuple**：一次性分配固定大小的连续内存，元素指针直接内嵌，**没有多余空间**。

因为结构固定，`tuple` 还能被 CPython 缓存复用——创建一个空的或短 `tuple` 时，解释器可能直接返回已有的对象，连分配都省了。

**实战影响**：读一千万行数据时，用 `tuple` 存每一行比用 `list` 省下的内存是实打实的，还能提速一点点（少了一层间接寻址）。

## 三、函数默认参数为什么不能写 `[]`

这是新手最常踩的坑，而且它跟"可变/不可变"直接相关：

```python
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add_item('a'))   # ['a']
print(add_item('b'))   # ['a', 'b']   ← 不是你以为的 ['b']
```

原因：**默认参数只在函数定义时求值一次**，`bucket` 从头到尾指向同一个 list 对象。每次调用 `append` 都在改这个共享对象。

正确写法是拿 `None` 当哨兵：

```python
def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

如果确实需要一个"会累积"的默认值，那就用不可变类型：

```python
def add_item(item, bucket=()):
    return bucket + (item,)     # 每次返回新 tuple，不污染默认值
```

## 四、可读性与"意图表达"

这点最容易被忽视，但影响最大。

`tuple` 在 Python 里通常表示**一个结构固定的记录**——长度不会变，每一项有明确位置含义：

```python
# 一行数据库记录：(学号, 姓名, 年龄)
row = (1001, '张三', 20)
sid, name, age = row        # 解包，语义清晰
```

`list` 表示**一串同类的东西**——数量可能变化，顺序有意义但不固定：

```python
scores = [88, 92, 75, 96]   # 长度会变，都是分数
```

所以判断标准不是"我会不会去改它"，而是：**这东西是"一条记录"还是"一堆东西"？**

- 一条记录（坐标、RGB、数据库行）→ `tuple`
- 一堆东西（待办列表、查询结果）→ `list`

顺带一个好处：用 `tuple` 当函数参数或返回值时，等于无声地告诉读代码的人"这里不会就地修改"。

## 总结对照表

| | list | tuple |
|---|---|---|
| 可变 | ✅ | ❌ |
| 可哈希（当字典键） | ❌ | ✅（元素全可哈希时） |
| 内存 | 更大（有超额分配） | 更小 |
| 能否增删 | ✅ | ❌ |
| 语义 | 一串同类元素 | 一条固定结构的记录 |
| 适合场景 | 会增删的集合 | 坐标、配置项、数据库行、函数多返回值 |

## 自测

1. `d[(1, [2, 3])] = 'x'` 能跑吗？——不能，tuple 里装了 list，整个 tuple 不可哈希。
2. 函数默认参数为什么不能用 `[]`？——默认值只求值一次，会被所有调用共享。
3. 一千万行数据该用哪个存？——tuple，省内存且访问略快。
4. 判断该用哪个的准则是什么？——是"一条记录"还是"一堆东西"。
