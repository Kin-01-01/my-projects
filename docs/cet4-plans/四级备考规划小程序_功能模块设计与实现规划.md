# 四级备考规划小程序 · 功能模块设计与实现规划

> 面向考试：**2026-12-12（英语四级 CET4，9:00–11:20）**，官方考期已核实
> 今天：2026-09-28 → **剩余 75 天**
> 定位：**私人备考规划师**（打卡式，告诉你"今天该干嘛"），**不是题库/词库 App**
> 硬约束：**不内置任何题库、试题库、单词词库**；所有学习内容由用户自行录入或导入
> 文档版本：v2（按"不内置内容"约束重写，替代《抓取清单与综合计划》）

## 0. 审核结论（先说重要的）

### 0.1 对新约束的判定 —— 方向更稳，但要补一个"框架"缺口
"不内置任何内容"这条约束**是对的**，它让产品边界清晰、不踩版权坑、不背"内容质量"的锅。但它和你的核心痛点（"没经验、英语不好、不知道从哪开始"）产生一个**张力**：

- 空 App + 一切自己填 → 你还是不知道"该填什么、怎么排"，等于没解决"没思路"的问题。
- **解法（本规划采用）**：App 不持内容，但提供**"规划框架 / 模板生成器"**——向导生成"三段空日程 + 每日空任务占位"，占位只写"该做什么类型的事"（如`基础期·词汇：导入你的词书第1–3单元`），你把自己的材料绑上去即可。**给结构、不给内容**，既守约束，又救"没思路"。

### 0.2 对旧计划的三处修正
1. **去掉"内置素材库"**：原《抓取清单》里的 GitHub 真题库 / 网盘瑞斯拜讲义 / B站体系，**不再作为 App 内置内容**，降级为"用户可导入的规划模板包 / 内容来源参考"（见 §7、§9）。
2. **三阶段切分要重锚**：原"基础60%/专项30%/模考10–15%"对 75 天不成立——模考冲刺至少需 2–3 周，10% 只有 7 天太少。**改为锚定末段法**（见 §3）。
3. **倒计时基准锁定 2026-12-12**，并补关键节点（报名截止/口试/准考证/考试日）。

### 0.3 内置"四级英语" skill 的角色重定
该 skill 含刘晓燕《你还在背单词吗》48 课（词以群记 + 词根词缀，结构化 JSON）——**高质量但不内置进 App**。它的正确用法是：作为"词汇"任务类型的**推荐导入/参考源**，你自行决定要不要把它的课表映射成自己的任务。App 不持有这 48 课的词。

## 1. 产品边界与核心概念

| 概念 | 说明 | 是否内置 |
|------|------|---------|
| **考试档案** examProfile | 考试日期、每日可用时长、目标分、当前水平 | 用户填，存云库 |
| **任务** Task | 某天某类学习活动（标题 + 类型 + 时长 + 计划日 + 状态） | 用户建/导入，**内容不内置** |
| **内容引用** contentRef | 任务指向"用户自己的材料"（如"导入包#瑞斯拜词汇 第3课""我的词书U2"），仅指针/备注 | 用户填 |
| **导入材料索引** Import | 记录"我有哪些材料可用"（名称/类型/来源备注），**不存内容本体** | 用户录 |
| **规划框架** Plan | 由向导生成的空日程骨架（结构，非内容） | 算法生成 |

**铁律**：App 数据库里只有"任务"和"指针"，没有任何一道题、一个词、一篇范文的正文。

## 2. 全局架构

- **前端**：微信原生小程序（WXML/WXSS/JS），tabBar 5 页（今日 / 日历 / 规划 / 进度 / 我的）
- **后端**：微信云开发 CloudBase（云数据库 + 云函数 + 云存储）
  - 云数据库：存 profile / tasks / checkins / reviewNodes / imports
  - 云函数：规划引擎生成、复习提醒定时推送、订阅消息下发
  - 云存储：仅存用户自己上传的材料文件（可选），App 不预置
- **账号**：微信 openid 静默登录，单用户自用，无复杂权限
- **视觉**：学术质感（纸色 #F7F4EC 背景、墨色 #2B2B2B 正文、衬线标题、墨绿/暗红点缀、大留白）

## 3. 备考节奏模型（75 天锚定切分）

> 不用"百分比"，改用**锚定末段法**：模考冲刺固定占最后一段，其余往前推。

| 阶段 | 时间窗（以 12-12 倒推） | 天数 | 核心任务类型（空占位，内容用户绑） |
|------|------------------------|------|-----------------------------------|
| **基础夯实期** | 09-28 → 11-19 | ~53 天 | 词汇积累、语法/长难句、听力输入 |
| **专项突破期** | 11-20 → 11-30 | ~11 天 | 阅读/听力/写作/翻译 分项突破 |
| **模考冲刺期** | 12-01 → 12-12 | ~12 天 | 真题套卷模考 + 查漏 + 准考证(12-1) |

> 说明：75 天偏紧，专项期被压缩。若你每天能投入 ≥1.5h，专项期可前移到 11-13 起。阶段边界在 App 里由 `examDate` 动态算，**改考试日自动重排**。

**关键里程碑（倒计时模块要标红）**：
- 🔴 报名截止（各省 9 月中下旬，**今天就要查学校通知**）
- 口试 CET-SET4：11-21
- 准考证打印：12-01 09:00 起
- 笔试：12-12 09:00–11:20

## 4. 功能模块设计（逐条对应你的需求）

### M1 · 考试倒计时显示
- 首页顶部大号："距考试 **75** 天"（每日 00:00 重算，基于 profile.examDate）
- 副信息：考试日期、星期、当前所处阶段标签（基础/专项/模考，动态）
- 关键节点条：报名/口试/准考证/考试 四个锚点，临近变红+提示
- 边界：考试日当天显示"今天考试"，过期显示"已结束"

### M2 · 任务模型 + CRUD（创建/编辑/删除/完成标记）
**任务实体字段**（云库 `tasks` 集合）：
```
_id, openid,
title,                 // 任务标题，如"词汇：词书U2 第1组"
type,                  // 词汇|听力|阅读|写作|翻译|模考|自定义
contentRef,            // 内容指针/备注（用户自己的材料），非内置内容
planDate,              // YYYY-MM-DD 计划日
slot,                  // 时段（早/中/晚）可选
estMinutes,            // 预计时长
status,                // 0待做 | 1已完成 | 2跳过
stage,                 // 基础|专项|模考（自动按 planDate 归类）
source,                // 手动 | 规划生成 | 导入
reviewOf,              // 若本任务是复习，关联源任务 _id
createdAt, completedAt
```
**操作**：新建（选类型/填标题/计划日/时长/绑材料）、编辑、删除（删前确认）、一键标记完成（completedAt 写入、触发进度+复习节点生成）。

### M3 · 每日 / 每周学习任务安排（规划引擎）
- **向导采集**（首次/设置里）：examDate(默认 2026-12-12)、dailyMinutes、targetScore、level → 存 profile
- **生成空日程**：按 §3 三段 + dailyMinutes 切块（每块 15–20min = 一个任务），产出 `tasks` 占位行（type + 标题占位 + planDate），contentRef 留空待绑
- **今日视图**：按 planDate=今天 拉任务列表，分组展示 + 勾选
- **本周视图**：本周 7 天任务矩阵
- **轻量自适应**：某任务未完成 → 提供"顺延至明日"；越近考试模考密度自动加（生成时末段多排模考）

### M4 · 学习进度追踪
- 今日进度环（今日完成/计划数）
- 阶段进度条（本阶段已完成任务占比）
- 连续打卡天数（streak）、累计学习时长（sum estMinutes of 已完成）
- 进度页：周/阶段/总计三档统计 + 简单走势

### M5 · 复习节点提醒
- **复习节点生成**：任务标记完成后，按间隔（默认 1/2/4/7/15 天，或简单"N天后"）生成 `reviewNodes`（关联到原任务，contentRef 复用）
- **提醒方式（两层）**：
  1. **应用内**（必做）：今日任务里单列"待复习"区，打开即见，无需授权
  2. **微信订阅消息**（阶段三）：打卡完成时弹"订阅复习提醒"→ 云函数定时扫 dueDate → 经订阅消息 API 推送"今日有 N 个复习"
- **技术坑**：小程序**不能后台常驻推送**，订阅消息需用户主动触发订阅（一次性或长期模板），服务端才能推。这是"提醒"唯一合规路径，规划里要明确。

### M6 · 时间轴 / 日历视图
- **日历（月视图）**：自绘轻量网格（控包体积），有任务的日期打点/角标，点日期看当天任务；阶段边界用底色区分
- **时间轴（横向）**：按阶段/周展示，标"今天位置""各阶段起止""关键里程碑"，一眼看清进度
- 实现建议：优先自绘（避免引入大组件库撑爆 2MB 主包）；若用 vant-weapp/uview 的 calendar，注意分包

### M7 · 设置 / 首次向导
- 首次打开 → 向导（M3 采集项）；之后"我的"页可改
- 含：考试日、每日时长、目标分、当前水平、清空重排

### M8 · 导入 / 录入（内容用户自理）
- **录入**：添加"我的材料"索引（名称/类型/来源备注：网盘/B站/GitHub/本地），**只记索引不存内容**
- **导入包（推荐，见 §9）**：把"规划模板包"一键导入 → 批量生成空任务占位（结构），内容仍由你持有
- **铁律提示**：导入的是"任务框架"，不是题目/单词；App 永远不持内容

|------|---------|------|
| `profile` | openid, examDate, dailyMinutes, targetScore, level, createdAt | 单用户档案 |

## 6. 规划引擎算法（逻辑伪码）

```
输入: profile(examDate, dailyMinutes, level, target)
1. 算剩余天数 D = examDate - today
2. 切三段: 模考=[examDate-12d, examDate]; 专项=[模考.start-11d, 模考.start]; 基础=[today, 专项.start]
3. 每日块数 N = floor(dailyMinutes / 18)   // 每块~18min
4. for each day d in [today, examDate):
     stage = 归属阶段
     按 stage 的任务类型配比，生成 N 个空任务(type + 占位标题 + planDate=d + estMinutes≈18)
     contentRef = ""  // 留空
5. 末段(模考)提高"模考"类型占比
6. 写入 tasks(source="规划生成")
输出: 空日程骨架（用户后续绑材料 / 手动增删）
```
**顺延**：某日未完成 → 用户点"顺延"→ 那些 task.planDate += 1。

## 10. 关键风险与技术坑

1. **报名截止（今天/这几天）**：真人动作，App 外，立即查学校通知。
2. **微信订阅消息限制**：提醒不能后台推，必须用户主动订阅 + 云函数下发，规划里已分层处理。
3. **主包体积 ≤ 2MB**：日历/组件优先自绘或分包。
4. **倒计时边界**：考试当天/过期需特殊处理，时区用北京时间。
5. **75 天偏紧**：规划必须现实，专项期已被压缩，别贪多排满。
6. **框架 vs 内容张力**：务必用 §0.1 的"框架生成器"补缺口，否则空 App 解决不了"没思路"。
